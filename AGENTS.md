# AGENTS.md

## Commands

```bash
npm run dev        # Vite dev server on port 3000
npm run build      # Production build
npm run lint       # ESLint only
npm run format     # Prettier --write . && eslint --fix
npm run check      # Prettier --check . (CI-friendly format check)
```

There is no test suite or typecheck script. `npm run check` only validates formatting, not types.

## Architecture

Single-page React admin dashboard ("Mercy Daily") for a faith/community platform.

**Stack:** React 19, TanStack Router (file-based), TanStack Query, Tailwind CSS v4, shadcn (radix-nova), Framer Motion, Vite 8.

**Route groups** (TanStack Router layout routes under `src/routes/`):
- `__auth/` — public auth pages (signin, forgot/reset password, verification). Split layout: image left, form right.
- `__main/` — authenticated admin pages. Layout: sidebar + header + animated `<Outlet>`.

**Adding a new page:**
1. Add a route file under `src/routes/__main/<name>.tsx`
2. Register the module in `src/lib/module.ts` (key, path, permissions) — this is the **single source of truth** for sidebar links, breadcrumbs, and permission matrix. Never duplicate the module list elsewhere.
3. Add an icon mapping in `src/lib/module-icons.tsx`

**Container/Presenter pattern** (ADR-0008): Route files own data fetching/mutations. UI components in `src/components/shared/` are pure presenters that accept data via props. See `user-management.tsx` → `user-management-ui.tsx` as the reference implementation.

## Generated files

`src/routeTree.gen.ts` is auto-generated by TanStack Router plugin. Never edit manually. It is excluded from linter, formatter, file watcher, and search in `.vscode/settings.json`.

## Path aliases

Both `#/*` and `@/*` resolve to `./src/*`. `@/*` is the standard convention. `#/*` appears in some type-only imports.

## API layer

`src/lib/api/base.ts` exports `baseURL` from `VITE_APP_SERVER` env var and a `request()` function. **The API is currently mocked** — `request()` simulates a 500ms delay and returns empty data. Real backend integration is pending. Only env var used: `VITE_APP_SERVER`.

## Styling

- Brand color: olive green `#53624D` — used for primary, sidebar background, table headers, hero banners.
- Theme defined via CSS custom properties in `src/styles.css` (light + `.dark` mode).
- shadcn components use **radix-nova** style (see `components.json`). New UI components go in `src/components/ui/` and use aliases from `components.json`.
- Prettier: no semicolons, single quotes, trailing commas, tab width 4, print width 140.

## Key shared components

- `src/components/shared/data-table.tsx` — reusable table with pagination, loading skeleton, empty state. Wraps content in `overflow-x-auto` for horizontal scroll.
- `src/components/shared/stat-card.tsx` — KPI stat cards. Use for all stat/metric displays (ADR-0003). Do not create ad-hoc card layouts for stats.
- `src/components/shared/filter-builder.tsx` — filter builder with `FilterState` type for URL-serialized filter queries.

## Animation

Use `src/lib/motionTokens.ts` for animation durations, easings, and distances. Do not hardcode magic numbers for Framer Motion transitions.

## ADRs

Eight architecture decision records exist in `docs/adr/`. Read them before making changes to established patterns. Key ones:
- ADR-0003: Reuse StatCard for all KPI displays
- ADR-0006: DataTable handles its own overflow scroll
- ADR-0008: Container/Presenter pattern for decoupling data from UI
